## Описание
Проект реализует систему журналирования сообщений с фильтрацией по уровням важности и асинхронной записью в файл.

### Часть 1. Динамическая библиотека `liblogger.so`
Библиотека предоставляет потокобезопасный singleton-логгер со следующим функционалом:
- Запись текстовых сообщений в файл с временными метками
- Три уровня важности: `STATE1`, `STATE2`, `STATE3`
- Фильтрация сообщений по пороговому уровню
- Динамическое изменение уровня важности по умолчанию
- Автоматическое создание директорий для файла журнала
- Потокобезопасная запись через мьютекс

### Часть 2. Консольное приложение `logger_app`
Многопоточное приложение, демонстрирующее работу библиотеки:
- Интерактивный ввод сообщений через консоль
- Асинхронная запись через отдельный поток-воркер с очередью
- Потокобезопасная передача данных (Producer-Consumer паттерн)
- Изменение уровня важности "на лету"
- Корректное завершение с ожиданием обработки всех сообщений

## Уровни важности
| Уровень   | Числовой код | Описание                                         |
|-----------|-------------|---------------------------------------------------|
| `STATE1`  | 0           | СУПЕР ВАЖНО                                       |
| `STATE2`  | 1           | Просто важно                                      |
| `STATE3`  | 2           | Вообще не важно - просто информация о работе и тп |

### Логика фильтрации
**Правило:** сообщение записывается, если его числовой код **≤** порогового значения.  
Меньшее число = большая важность.

Если установлен порог STATE2:
OK  STATE1 (0) — записывается (важнее порога)
OK  STATE2 (1) — записывается (равен порогу)
BAD STATE3 (2) — отбрасывается (менее важен чем порог)

## Формат журнала
Каждая запись в файле журнала имеет следующий формат:
```text
[YYYY-MM-DD HH:MM:SS.mmm] [LEVEL] текст сообщения
```
| Поле	          | Описание	                        | Пример                                   |
|-----------------|-----------------------------------|------------------------------------------|
| YYYY-MM-DD      |	Дата	                            | 2026-07-08 (У МЕНЯ СКОРО ДЕНЬ РОЖДЕНИЯ!) |
| HH:MM:SS	      | Время (24-часовой формат)         |	15:30:45                                 |
| mmm             |	Миллисекунды (с ведущими нулями)	| 123                                      |
| LEVEL           |	Уровень важности         	        | STATE1, STATE2, STATE3                   |
| текст сообщения |	Пользовательское сообщение        | БД отпала, сервера сгорели.              |

## Технические детали
### Паттерны проектирования
- Singleton (Meyer's) в	Logger. Обоснование:	единственная точка записи в файл, потокобезопасная инициализация.
- Producer-Consumer	в AsyncWriter. Обоснование:	Разделение ввода и записи для отзывчивости интерфейса.
- RAII	в AsyncWriter, Logger. Обоснование:	Автоматическое освобождение ресурсов (файл, поток).
### Потокобезопасность
- Atomic operations:  initialized_ и defaultLevel_ используют std::atomic с явными memory_order для корректной синхронизации без лишних блокировок
- Mutex:              writeMutex_ защищает файловый поток от одновременной записи
- Condition Variable: cv_ в AsyncWriter обеспечивает эффективное ожидание без busy-waiting
### Обработка ошибок
- Ошибки открытия/записи файла выводятся в stderr
- Исключения при записи перехватываются и логируются
- Невалидный пользовательский ввод отклоняется с пояснением
- Shutdown-сообщение гарантирует запись всех pending messages перед выходом
### Совместимость
- C++17: использование std::filesystem, std::optional-подобных паттернов
- Linux: localtime_r для потокобезопасной работы со временем
- Переносимость: код легко адаптируется под Windows (замена localtime_r на localtime_s)
